# gymOS — Product Requirements Document
**Version:** 1.0
**Date:** 2026-06-03
**Status:** implemented
**Spec reference:** docs/specs/2026-06-03-gymos-mvp.md

---

## 1. Problem

Serious lifters training 5x/week have no data. Every manual logging app — Strong, Hevy, JEFIT — requires pulling out your phone between sets, unlocking it, finding the exercise, typing numbers. That's 20–30 seconds of friction per set, 10–15 sets per session. People stop doing it after week two.

The result: you're training on pure feel. You don't know if your bench volume went up this month. You don't know if you're actually getting stronger or just maintaining. You can't see when you're overreaching before you get hurt.

**The core failure:** logging tools were designed around the phone, not the barbell.

---

## 2. Vision

An Apple Watch app where the only thing you do is tap the exercise and lift.

The watch counts your reps. You confirm weight in under 10 seconds after the set. Everything else — rest detection, session tracking, progress trends — happens automatically. You finish your workout and open your phone to see whether you're getting stronger.

No accounts. No cloud. No friction.

---

## 3. Target User

**Primary:** Kevin — trains 5x/week, compound lifts (bench, squat, deadlift, OHP, rows, pull-ups). Serious about progression. Has tried logging apps and abandoned them due to friction. Owns an Apple Watch. Wants data, not gamification.

**Characteristics:**
- Trains consistently (3–5x/week minimum)
- Does barbell/bodyweight compound movements
- Cares about progressive overload — wants to know if weight/volume went up week-over-week
- Not interested in social features, coaching, or nutrition
- Will not tolerate an app that breaks their lifting flow

**Not the target user (MVP):**
- Beginners who need coaching or form guidance
- Cardio / HIIT / CrossFit athletes
- People who want a social/community experience
- Gym-goers who primarily use machines

## 4. User Personas

### Persona A — "The Volume Tracker"
**Profile:** 28, lifts 5x/week, follows a PPL program. Tracks bench press obsessively. Wants to see if weekly chest volume is trending up. Currently uses a whiteboard at home.

**Pain:** No historical data. Can't tell if a good session was actually good or just felt good.

**Job to be done:** *"When I finish a session, show me whether I did more or less volume than last week — without me doing anything during the workout."*

### Persona B — "The Strength Athlete"
**Profile:** 34, trains for strength. Cares about 1RM progression. Currently tracks in a spreadsheet, which he updates after the gym.

**Pain:** Spreadsheet doesn't give trends automatically. Has to do math himself.

**Job to be done:** *"Show me if my estimated 1RM is trending up over the past 3 months."*

### Persona C — "The Distracted Lifter"
**Profile:** 25, trains 4x/week but loses count of reps mid-set when gym is loud or he's mentally fatigued.

**Pain:** Loses count at rep 7 or 8. Reracks uncertain whether he hit 8 or 9. Can't trust his own rep counts.

**Job to be done:** *"Count my reps for me so I can focus on the lift, not the number."*

## 6. UX Flows

### 6.1 Full Lifting Session Flow
```
BEFORE FIRST SET
─────────────────────────────────────────────────
iPhone or Watch:
  [Bench] [Squat] [Pull-up] [OHP] [Row]
         ↓ tap "Bench"
  Session created, exercise locked to Bench Press
  Watch face: "BENCH PRESS — Ready"

DURING SET
─────────────────────────────────────────────────
User starts lifting
Watch face: "BENCH PRESS"
            "  7  " ← live rep count, updates each rep
Rep detection running via CoreMotion

SET ENDS (3s no motion detected)
─────────────────────────────────────────────────
Watch vibrates (haptic)
Watch face: "Set complete — 8 reps"
            "Weight: [135 lbs] ↕"  ← Digital Crown to adjust
            [Confirm]  [30s countdown]

User scrolls to 155 lbs → taps Confirm
Set saved: Bench, 8 reps, 155 lbs

BETWEEN SETS (rest)
─────────────────────────────────────────────────
Watch face: "Last set: 8 × 155 lbs"
            "Volume: 1,240 lbs"
            [Same exercise] or [Change exercise]

SWITCHING EXERCISE
─────────────────────────────────────────────────
User taps "Change exercise"
Picker appears: [Bench] [Squat] [Pull-up] [OHP] [Row]
User taps "OHP" — locked for next set

SESSION END
─────────────────────────────────────────────────
User taps "End Session"
Confirm dialog: "End session? X sets logged."
Confirms → session closes → syncs to iPhone

iPhone notification (if available): "Session synced"
```

### 6.2 Weight Timeout Flow
```
Set ends → weight confirmation prompt appears
         ↓ user doesn't respond
         30s countdown visible on screen
         ↓ countdown reaches 0
Auto-save: last known weight for that exercise (or 0 lbs if first set)
Set flagged with ⚠ icon in session history
User can see flagged sets in iPhone session detail
```

### 6.3 iPhone Progress Flow
```
iPhone App — Tab Bar:
  [Sessions]  [Progress]  [Settings]

Sessions tab:
  List: date, exercises, total volume
  Tap session → detail view:
    Per exercise: sets × reps × weight, volume, velocity sparkline
    ⚠ icon on flagged (auto-saved) sets

Progress tab:
  Muscle Group Volume — bar chart, 8 weeks
  Bench 1RM Trend — line chart with ±10% band, 12 weeks
  (Selector: which exercise for 1RM — bench only in MVP)
```

## 7. Edge Cases & Error Handling

| Scenario | Expected Behavior |
|----------|------------------|
| User lifts before selecting exercise | Rep detection does not start; watch shows "Select exercise first" |
| User changes exercise mid-set | Not possible — picker disabled once set begins |
| Watch loses connection to iPhone mid-session | Session data stored locally on watch; syncs when connection restores |
| User forgets to end session; leaves gym | Auto-end after 20 min of inactivity; session saved |
| 0 reps detected (false set start) | Set discarded if 0 reps confirmed — user can cancel at weight prompt |
| Weight confirmation timeout on first-ever set | Auto-saves with 0 lbs, flagged — user must correct manually on iPhone |
| App crashes mid-session | Completed sets already saved to SwiftData; in-progress set lost (acceptable for MVP) |
| User does 2 reps (warmup) then walks away | 3s quiet → weight prompt; user can cancel to discard |
| Very slow reps (tempo lifting, > 3s per rep) | Rep not counted — documented limitation for v1; v2 adds tempo mode |
| Watch not worn on dominant wrist | Accuracy degrades — settings note recommends dominant wrist for lifting |

## 8. Non-Functional Requirements

| Requirement | Target |
|-------------|--------|
| Rep detection latency | < 500ms from rep completion to count update |
| Rest detection trigger | Within 1s of 3s quiet period |
| Weight sync Watch → iPhone | < 30s after session end |
| App launch to first set ready | < 3s |
| Battery impact | < 15% Watch battery per 60-min session |
| Data persistence | All confirmed sets survive app restart and OS crash |
| Storage | < 50MB for 1 year of daily sessions |
| Minimum OS | watchOS 10, iOS 17 |
| Minimum hardware | Apple Watch Series 6, iPhone 12 |

## 9. Data Model

```
Exercise
  id: UUID
  name: String               — "Bench Press"
  shortName: String          — "Bench"
  muscleGroup: MuscleGroup   — chest | legs | back | shoulders
  dominantAxis: Axis         — x | y | z
  motionDirection: Direction — push | pull | up | down
  repMinDuration: Float      — 0.3s
  repMaxDuration: Float      — 3.0s
  accelerationThreshold: Float — tuned per exercise

WorkoutSession
  id: UUID
  startTime: Date
  endTime: Date?
  sets: [WorkoutSet]

WorkoutSet
  id: UUID
  sessionId: UUID
  exerciseId: UUID
  timestamp: Date
  reps: Int
  weightLbs: Float
  velocitySamples: [Float]   — peak acceleration per rep
  autoSaved: Bool            — true if weight not confirmed by user

UserSettings
  weightUnit: WeightUnit     — lbs | kg  (display only; storage always lbs)

MuscleGroup: chest | legs | back | shoulders
```

**Computed (not stored):**
- `WorkoutSet.volume` → `weightLbs × Float(reps)`
- `WorkoutSet.epley1RM` → `weightLbs × (1 + Float(reps) / 30.0)`
- `WorkoutSet.epley1RMUpperBound` → `epley1RM × 1.10`
- `WorkoutSet.epley1RMLowerBound` → `epley1RM × 0.90`
- `WorkoutSession.volumePerExercise` → `[UUID: Float]`
- `WorkoutSession.bestSet` → set with highest `volume`

## 11. Out of Scope (MVP)

| Feature | Rationale | Target |
|---------|-----------|--------|
| Exercise auto-identification via ML | Solved better by manual selection; ML adds complexity without UX benefit | v2 |
| Background rep detection (screen off) | WatchKit limitation; requires always-on display entitlement | v2 |
| Haptic feedback per rep | Nice to have; not core to value prop | v2 |
| Rest timer with alerts | Users know their rest periods; adds noise | v2 |
| iCloud sync | Account complexity; local-first is a feature for privacy | v2 |
| Additional exercises beyond 5 | Validate core loop first | v2 |
| RPE / perceived exertion logging | Adds friction at weight confirm step | v2 |
| Program / workout planning | Different product surface entirely | v3 |
| Social features | Not the target user's need | v3 |
| Nutrition tracking | Out of scope entirely | v3 |
| Form feedback | Requires camera or ML; different safety risk profile | v3 |

## 13. Open Questions

All resolved for MVP:
- **Rep detection method:** threshold + duration gating, deterministic (no ML) ✓
- **Exercise selection:** manual tap, not auto-detect ✓
- **Weight units:** lbs default, kg toggle, stored in lbs ✓
- **Session definition:** starts on first exercise selection, ends on tap or 20min inactivity ✓
- **Multi-exercise sessions:** supported, exercise changes between sets only ✓
- **Sync mechanism:** WatchConnectivity, local SwiftData only ✓
