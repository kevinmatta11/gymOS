# Spec: gymOS MVP — Automatic Lift Tracking on Apple Watch
**Date:** 2026-06-03
**Status:** approved

---

## Problem
Training 5x/week with zero data. No rep tracking, no volume visibility, no progress trends.
Pure guesswork on whether you're improving. Manual logging apps require a phone, break flow,
and get abandoned after week two.

## Solution
An Apple Watch app that automatically detects reps via accelerometer — no phone, no tapping,
no logging. You lift. It counts. After the set, you confirm weight on the watch face.
An iPhone companion app shows progress trends that actually tell you if you're getting stronger.

### Explicitly NOT in MVP
- Exercise auto-identification (user selects exercise manually at session start)
- Form feedback or injury detection
- Social features, sharing, leaderboards
- Nutrition tracking
- AI coaching or program generation
- Android / Wear OS support
- Cloud sync / multi-device (local only for MVP)

---

## User Stories

**Lifting**
- As a lifter, I want the watch to count my reps automatically so I never lose count mid-set
- As a lifter, I want to see my live rep count on my wrist during the set
- As a lifter, I want the watch to detect when I'm resting so I don't have to tap anything
- As a lifter, I want to confirm weight quickly after each set (10 seconds max)

**Session Review**
- As a lifter, I want to see total volume per exercise when I finish a session
- As a lifter, I want to see bar velocity trend per set so I know when I was close to failure

**Progress**
- As a lifter, I want to see weekly volume per muscle group over time
- As a lifter, I want to see my estimated 1RM trend for bench press over time
- As a lifter, I want to see my best set per session so I can track PRs

## Core Features (MVP)

### 1. Auto Rep Detection
- **Sensor:** Apple Watch accelerometer (CoreMotion)
- **Method:** Motion pattern recognition per exercise — each of the 5 exercises has a
  distinct wrist acceleration signature; classify rep completion via threshold crossing
  on the dominant axis + duration gating (min 0.3s per rep, max 3s per rep)
- **Supported exercises (v1):** bench press, back squat, pull-up, overhead press, barbell row
- **Live display:** rep count updates in real time on watch face during set
- **Set end detection:** 3+ seconds of no rep-pattern motion → prompt weight confirmation

### 2. Set Tracking
- **Rest detection:** accelerometer quiet period ≥ 3s after last rep triggers set-end
- **Weight confirmation:** Digital Crown scroll or +/- tap on watch; pre-fills last used weight
  for that exercise; must confirm within 30s or set is auto-saved with last weight + flag
- **Data stored per set:** exercise_id, timestamp, reps (int), weight (float, lbs or kg),
  velocity_samples (array of floats), session_id
- **Session start:** user selects exercise from list of 5 on watch; new session auto-created

### 3. Session Summary (iPhone companion)
- **Trigger:** session ends (user taps "End Session" on watch or 20min inactivity)
- **Displayed per exercise:**
  - Total volume = Σ(sets × reps × weight)
  - Sets completed
  - Bar velocity trend: normalize velocity samples per set, plot fast→slow as a sparkline
    (approaching failure = last set velocity < 60% of first set velocity → warning label)
- **Data sync:** Watch → iPhone via WatchConnectivity framework; local SwiftData store

### 4. Progress Trends (iPhone)
- **Weekly volume per muscle group**
  - Muscle group mapping: bench→chest, squat→legs, pull-up/row→back, OHP→shoulders
  - Displayed as bar chart, trailing 8 weeks
- **1RM trend (bench press)**
  - Formula: Epley — `weight × (1 + reps / 30)`
  - Displayed per session as a line chart, trailing 12 weeks
  - Show ±10% confidence band — never display as exact
- **Best set per session**
  - Best set = highest volume set (weight × reps) in that session
  - Shown in session history list

## Tech Stack
- **Watch app:** SwiftUI + WatchKit, CoreMotion for accelerometer
- **iPhone app:** SwiftUI, SwiftData for local persistence
- **Sync:** WatchConnectivity (Watch → iPhone)
- **No backend for MVP** — fully local, no accounts, no network required

## Acceptance Criteria

### Rep Detection
- [ ] Bench press: detects reps within ±1 accuracy on sets of 3–15 reps in testing
- [ ] Squat: detects reps within ±1 accuracy on sets of 3–15 reps
- [ ] Pull-up: detects reps within ±1 accuracy on sets of 3–15 reps
- [ ] OHP: detects reps within ±1 accuracy on sets of 3–15 reps
- [ ] Barbell row: detects reps within ±1 accuracy on sets of 3–15 reps
- [ ] Live count updates on watch face without lag > 500ms after rep completes
- [ ] No false positives during 60s rest period (0 phantom reps counted)

### Set Tracking
- [ ] Rest detection triggers set-end prompt within 1s of 3s quiet period
- [ ] Weight confirmation UI operable in < 10s
- [ ] Weight pre-fills from last set of same exercise in current session
- [ ] Set saved correctly: exercise, reps, weight, timestamp, session_id
- [ ] Auto-save with flag fires correctly if confirmation not completed in 30s

### Session Summary
- [ ] Total volume per exercise calculated correctly: Σ(sets × reps × weight)
- [ ] Velocity trend sparkline renders for any session with ≥ 2 sets
- [ ] Failure warning label shows when last set velocity < 60% of first set velocity
- [ ] Summary visible on iPhone within 30s of session end on watch

### Progress Trends
- [ ] Weekly volume chart renders correctly for trailing 8 weeks with real data
- [ ] 1RM trend uses Epley formula exactly: `weight × (1 + reps / 30)`
- [ ] 1RM displays with ±10% confidence band, not as exact value
- [ ] Best set per session shown in session history list

### Data Integrity
- [ ] All set data persists across app restart (no data loss)
- [ ] Weight values validated: positive, < 2000 lbs
- [ ] Rep counts validated: positive integer, < 200
- [ ] No user data sent over network (fully local)

---

## Fitness Domain Constraints
- 1RM estimates use Epley formula — displayed as estimate with ±10% band (per `.claude/rules/exercise-safety.md`)
- Max weekly progressive overload: 10% load increase per week tracked and surfaced (per `.claude/rules/user-progression.md`)
- No medical language — velocity failure warning says "approaching failure" not "injury risk"
- All workout data is append-only — no in-place edits, corrections create new records (per `.claude/rules/data-integrity.md`)

---

## Open Questions (resolved)
- **Rep detection method:** threshold + duration gating on accelerometer (not ML for MVP — keep it deterministic and auditable)
- **Weight units:** lbs default, kg toggle in settings (store in lbs internally, display in user preference)
- **Multi-exercise sessions:** user switches exercise on watch between sets; session continues

## Out of Scope
- Background rep detection (screen-off mid-set detection is a v2 problem)
- Haptic rep counting feedback (v2)
- Rest timer with alerts (v2)
- iCloud sync (v2)
- Exercise auto-identification via ML (v2)
