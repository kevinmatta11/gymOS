# Plan: gymOS MVP — Automatic Lift Tracking on Apple Watch
**Date:** 2026-06-03
**Spec:** docs/specs/2026-06-03-gymos-mvp.md
**Flow:** loop (4 parallel slices → integration)
**Status:** active

---

## Flow Decision: Loop (Parallel Slices)
The MVP has 4 clearly independent layers that can be built in parallel:
- Slice A and B share no code until integration
- Slice C depends on Slice B's data model (build B first, then C)
- Slice D depends on Slice B's data model (same)

**Build order:**
```
Slice A (Rep Detection Engine)  ──┐
Slice B (Data Model + Persistence)─┼──► Integration branch ──► /pr
Slice C (Watch UI)  ───────────────┘ (after B)
Slice D (iPhone App) ──────────────┘ (after B)
```

---

## Slice A — Rep Detection Engine
**Scope:** CoreMotion accelerometer pipeline, rep classification algorithm for all 5 exercises.
No UI. Pure logic, fully testable in isolation.

### Tasks
- [ ] A1: Set up Xcode project — gymOS Watch App + iPhone companion target, SwiftData shared framework
- [ ] A2: CoreMotion manager — start/stop accelerometer at 50Hz, buffer samples
- [ ] A3: Rep classifier — exercise is already known (user selected it), so classifier
      receives exercise context and applies that exercise's axis + threshold.
      No multi-exercise disambiguation needed.
      - Bench press: Y axis, push direction, threshold TBD via calibration
      - Squat: Z axis, downward, threshold TBD
      - Pull-up: Z axis, upward, threshold TBD
      - OHP: Z axis, upward (larger ROM than squat — separate threshold)
      - Barbell row: Y axis, pull direction, threshold TBD
- [ ] A4: Rest detector — 3s quiet period detection, fires set-end event
- [ ] A5: Velocity estimator — peak acceleration per rep as proxy for bar velocity
- [ ] A6: Unit tests for classifier — test each exercise with recorded motion fixtures
- [ ] A7: Calibration test harness — record real motion data, tune thresholds

### Definition of Done
- All 5 exercises detect reps within ±1 on sets of 3–15 (verified via fixtures)
- Rest detection fires within 1s of 3s quiet period
- Zero false reps during 60s simulated rest
- Velocity samples array populated per set
- `/verify` artifact in docs/reports/

## Slice B — Data Model + Persistence
**Scope:** SwiftData schema, all model types, local persistence, WatchConnectivity sync.
No UI. This is the shared foundation for Slice C and D.

### Tasks
- [ ] B1: SwiftData models
      - `Exercise` (id, name, muscleGroup, axisConfig)
      - `WorkoutSession` (id, startTime, endTime, sets:[WorkoutSet])
      - `WorkoutSet` (id, sessionId, exerciseId, timestamp, reps, weightLbs, velocitySamples:[Float], flagged:Bool)
      - `UserSettings` (weightUnit: lbs|kg)
- [ ] B2: Repository layer — `WorkoutRepository` with save/fetch/query methods
- [ ] B3: Seed data — 5 exercises with muscle group mappings
- [ ] B4: WatchConnectivity manager — transfers completed session from Watch to iPhone
- [ ] B5: Weight unit conversion helpers (lbs ↔ kg, store in lbs always)
- [ ] B6: Calculated properties
      - `WorkoutSet.volume` → weight × reps
      - `WorkoutSession.volumePerExercise` → [exerciseId: Float]
      - `WorkoutSession.bestSet` → highest volume WorkoutSet
      - `WorkoutSet.epley1RM` → weightLbs × (1 + Float(reps) / 30)
- [ ] B7: Unit tests — round-trip persistence, volume calculations, Epley formula correctness

### Definition of Done
- All models persist across app restart
- Volume and 1RM calculations match spec exactly
- WatchConnectivity transfers session data reliably
- Data validation enforced (weight > 0 and < 2000, reps > 0 and < 200)
- `/verify` artifact in docs/reports/

## Slice C — Watch UI
**Depends on:** Slice B complete (models available)
**Scope:** All WatchKit / SwiftUI views on the watch. Wires to Slice A engine and Slice B data.

### Tasks
- [ ] C1: Exercise picker — list of 5 exercises on Watch, tap to select and lock for the set;
         can change exercise between sets (not mid-set)
- [ ] C2: Active set view — large live rep counter, exercise name, current set number
- [ ] C3: Weight confirmation view — Digital Crown scroll + confirm button, pre-fills last weight,
         30s countdown, auto-save on timeout
- [ ] C4: Between-sets view — last set summary (reps × weight), next set prompt
- [ ] C5: End session button — available at any point, confirms before ending
- [ ] C6: Wire Slice A engine into C2 — live rep count from classifier updates view
- [ ] C7: Wire Slice B repository into C3 — save set on weight confirm

### Definition of Done
- Full lifting flow works end-to-end on Watch simulator
- Weight confirmation operable in < 10s
- Live rep count updates with < 500ms lag
- Set saved correctly to SwiftData after each confirmation
- `/verify` artifact in docs/reports/

---

## Slice D — iPhone App
**Depends on:** Slice B complete (models available)
**Scope:** All SwiftUI views on iPhone. Reads from Slice B's SwiftData store.

### Tasks
- [ ] D0: Exercise picker on iPhone — same 5 exercises, tap to start/switch; syncs active
         exercise selection to Watch via WatchConnectivity
- [ ] D1: Session history list — list of sessions, date + total volume + exercise names
- [ ] D2: Session detail view
          - Total volume per exercise
          - Sets completed
          - Velocity trend sparkline (sets in order, normalized velocity)
          - Failure warning label (last set velocity < 60% of first)
- [ ] D3: Progress tab — weekly volume bar chart (trailing 8 weeks, per muscle group)
- [ ] D4: 1RM trend chart — bench press Epley 1RM per session, trailing 12 weeks,
          ±10% confidence band rendered as shaded region
- [ ] D5: Settings view — weight unit toggle (lbs / kg)
- [ ] D6: Wire WatchConnectivity receive handler → SwiftData insert

### Definition of Done
- Session summary renders correctly for a seeded session
- Volume calculations match spec
- 1RM chart uses Epley exactly, shows ±10% band
- Velocity failure warning appears correctly (< 60% threshold)
- Weekly volume chart renders for 8 weeks of seeded data
- `/verify` artifact in docs/reports/

## Risks
- OHP vs Squat share Z axis — mitigated completely: exercise is known before set starts, each gets its own tuned threshold
- Digital Crown weight input UX on small watch screen — test early in C3
- WatchConnectivity reliability on simulator vs real device — flag for real device testing
- CoreMotion 50Hz sample rate may need tuning per Watch model (Series 6+ vs older)
